## 决策 1：三组必须分开，混算会夸大重叠的解释力

**错误做法**：把"命中"与"未命中"两类直接比。

**为什么错**：`sample` 的 4 条 implicit 查询 **bigram 全为 0 且全部未召回**。
它们与"重叠低"无关——是 lexical 根本没返回 gold。

把它们混进"未命中组"，未命中均值会被 0 拉低：

```
三组合并前：命中 0.1937 vs 未命中 0.0080   -> 差 0.1857
排除 C 组后：命中 0.1937 vs 未命中 0.0400   -> 差 0.1537
```

**夸大 20%**。而夸大的方向正好支持"重叠能解释 top-1"这个结论——
所以这是一个**会自我强化**的错误。

## 决策 2：必须做置换检验，不能只看均值差

n 只有 5 和 8。均值的标准误很大。

**精确置换检验**（穷举全部组合）：

| subject | 组合数 | 观察到的差值 | p |
|---|---|---|---|
| `sample` | C(6,5)=6 | +0.1837 | **0.0079** |
| `billing` | C(12,8)=495 | +0.0612 | **0.1091** |

**小 n 时穷举可行**（`itertools.combinations`），不需要正态近似。

**结果分裂是本次最重要的发现**：不能合并成一个说法。

## 决策 3：不写"lexical 高分 = 数据太容易"

**这个说法在 `sample` 上成立**：5 条 top-1 全部 bigram ≥ 0.05，均值 0.1937。

**在 `billing` 上不成立**：8 条 top-1 里 3 条 bigram < 0.05。

**为什么 `billing` 那 3 条能命中**：

| case | query | gold | 共享的是什么 |
|---|---|---|---|
| `c1` | 发票币种是怎么规定的？ | 国内客户的发票一律开人民币 | **"发票"的语义** |
| `c2` | 税务申报是按什么分的？ | 华北的客户在北京税局申报 | **"申报"** |
| `a3` | 德国那边的账怎么开 | 欧洲客户走欧元发票 | **德国↔欧洲** |

**这是语义相关**。而 bigram 抓不到"德国↔欧洲"这种关联。

**若强行统一结论**，会得出"billing 的数据也太容易"，
从而去加难度——而实际那 3 条是真实能力。

## 决策 4：`bigram` 的局限要登记，但不否定它

**它抓不到**：语义相关但字面不同（3 个实例）。

**它能抓到**：query 抄原文（`L3` 的用途，上限 0.50）。

**两者不冲突**：
- `L3` 防的是"抄"
- 本次分析问的是"top-1 靠不靠字面"

同一个指标，两种用途，结论不同。**不能因为第二种用途有局限就否定第一种。**

## 决策 5：不测 cosine，不定 v3 产物格式

用户的建议是"先回答 lexical 的 0.83 怎么来的"。本次就做这个，不越界。

**为什么不顺手测 cosine**：它无法从产物复算，写不进报告（上一轮已确认）。

**为什么不定 v3 产物格式**：格式取决于"cosine 是否参与排序"这个决策，
而那个决策还没做。先定格式会定错。

## Risks / Trade-offs

| 风险 | 缓解 |
|---|---|
| n 太小，结论可能不稳 | 置换检验给出 p 值；且明确写"sample 显著、billing 不显著" |
| bigram 指标有漏检 | 登记 3 个实例；不把它当唯一判据 |
| 两个 subject 结论分裂 | 这本身就是结论，不强行统一 |

## 不做的事

- **不测 cosine**
- **不定 v3 产物格式**
- **不加特征、不改融合**
- **不造 v3 数据**
- **不新增 results 文件**
