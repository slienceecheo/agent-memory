## 决策 1：用配对口径，不用"已召回 vs 全部"

**备选（我第一版写的）**：

```
lexical 单路 0.8333 (5/6 已召回)
三路融合     0.3000 (3/10)
```

**不可行**：分母不同（6 vs 10）。前者只算"召回了的"，后者算全部。

**与"两个 1.2%"同型**：同一个百分比的两种含义。
若这两个数字被并列写出来，读者会以为三路比 lexical 差 0.53，
而实际配对后差 0.33（sample）与 0.78（billing）。

**修正后**：只比较"两者都召回"的 case。

| subject | 配对 n | lexical | 三路 | 差 |
|---|---|---|---|---|
| `sample` | 6 | 5/6 | 3/6 | +0.3333 |
| `billing` | 9 | 8/9 | 1/9 | +0.7778 |

**结论不变，而且更保守。**

## 决策 2：三个分母都报

| 分母 | 用途 |
|---|---|
| 全部派生 within | 端到端（召回失败也算错） |
| 已召回 | 排除召回失败，只看召回了的 |
| 配对 | 重排本身的质量 |

**为什么不能只报一个**：
- 只报端到端 -> 把"三路召回少"算成"三路重排差"（而实际三路召回更全）
- 只报配对 -> 掩盖"三路召回更全"这个优点

**"全部派生 within"最能反映用户感受**（召回不到就是错），
**"配对"最能回答"重排有没有用"**。两个问题都需要答案。

## 决策 3：限定句必须写，且有断言守着

```
这不是"多路召回有害"。
多路召回提高了召回率，降低了 top-1 精度。
```

**为什么这条容易丢**：它看起来像"补充说明"，而补充说明最容易被精简。

**而丢掉它的代价**：读者把 `0.8333 → 0.5000` 读成"该砍掉 vector 路"。
而召回从 6/10 变 10/10 说明 vector 路是有用的——只是融合方式把它的长尾
变成了稀释。

**所以 `test_report_marks_fusion_dilution_not_multi_path_harm` 读文档文本，
断言这句限定在。**

## 决策 4：不新增结果文件

**我第一版写了** `results/conclusion5-lexical-vs-fusion.json`。
**实测顶层变成 49 个**，违反了"永远 48 个"。

**已删除，改为现场重跑**：

| 做法 | 问题 |
|---|---|
| 写结果文件 | 破坏 48 个约束 |
| 现场重跑 | 慢（~10 秒），但 embedding 走缓存，不调 API |

新增一个文件等于开了一个"临时产物可以放顶层"的先例。

## 决策 5：文档断言必须解析表格行

**我第一版写的**：

```python
for label in ("全部派生 within", "已召回", "配对"):
    assert label in section
```

**证伪时失败**：抽掉表格的 `| **配对（都召回）** |` 那一行，断言仍然通过——
因为 `"配对"` 在 §6 里出现 8 次（标题、正文、表格、§6.5 的表）。

**这是本项目反复出现的"字符串包含"形态**，与 §0.6 那两个 1.2% 同族。

**改成解析表格**：

```python
table = section.split("### 6.2")[1].split("### 6.3")[0]
rows = [ln for ln in table.splitlines() if ln.strip().startswith("|")]
first_cells = [第一列的单元格 for row in rows]
for label in ("全部派生 within", "已召回", "配对（都召回）"):
    assert label in first_cells
```

**为什么括号要包含在 label 里**：`| 已召回 |` 是其他行的前缀，
不带括号会匹配到"三路全召回"那一行。

## 风险与取舍

| 风险 | 缓解 |
|---|---|
| 现场重跑让测试变慢（~10 秒） | 可接受，且 embedding 走缓存 |
| 数字与报告会漂移 | `test_paired_comparison_matches_report` 逐项比对 |
| 方向断言与数值断言可能同时失效 | 两条分开写，各自能被单独违反 |

## 不做的事

- **不改融合算法**（加权 RRF、按路径长度归一化）：那是检索层变更，
  需要单独变更；而且改了之后这条基线就没了
- **不加第四特征**（cosine）：上限被 lexical 单路锁住，见 tasks.md §5
- **不造 v3 数据**
- **不新增任何 results 文件**
