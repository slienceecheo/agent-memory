## 决策 1：阈值用 0.01，不用 0.006

**用户建议 0.006，理由是 `cos(v1,v2)=0.9971` 换算后约 0.0056。**

**方向对，但这个值来自手推**（`sin(角度差) × θ`）。
我实测了真实旋转，结果是：

| 量 | 值 |
|---|---|
| 均值 | 0.0019 |
| P95 | **0.0051** |
| **最大** | **0.0061** |

**阈值 0.006 小于实测最大值 0.0061**——判据会落在自己的噪声边界上。

**所以用 0.01（1.6 倍）**，并把"为什么不用 0.006"写进报告。

## 决策 2：必须区分"缓存命中"与"未命中"

**用户说"非确定性存在"，但没说清它的作用范围。**

**实测**：

```
缓存命中：       max|diff| = 0.00e+00
缓存未命中：     cos = 0.9971
```

**这个区分是"能否复现"的关键**：

| 情形 | 能否复现 |
|---|---|
| 重跑同一份数据（缓存命中） | ✅ 逐位相同 |
| 首次生成缓存（未命中） | ⚠️ 有 0.0061 量级噪声 |

**`run_retrieval` 走缓存**，所以已产出的结果文件是冻结的。
**新数据的噪声只影响"首次生成"，之后不再变化。**

## 决策 3：负 gap 不计入"不稳定"

**这是本变更里最容易写错的地方。**

`cosine_gap < 0` 的含义是"gold 的 cosine 比最强干扰项还低"——
那不是"名次可能翻转"，是"**名次已经错了**"。

| subject | 正 gap 最小值 | `gap < 0.01` | 负 gap |
|---|---|---|---|
| `sample` | 0.0136 | **0** | **1** |
| `billing` | 0.0447 | **0** | **2** |

**若把负 gap 也算作"不稳定"**，会得出"`billing` 有 2/12 = 17% 的 case 不稳定"——
而那 17% 其实是 cosine 排错了，不是噪声。

**处置相反**：
- 不稳定 -> 记录并排除出结论
- 排错 -> 那是能力边界，不能排除

## 决策 4：`cosine_gap` 与 `tie_at_top1` 是同类

**用户提到 `tie_at_top1` / `tie_resolved_by` 是现成先例，我同意。**

| 字段 | 记录什么 | 用途 |
|---|---|---|
| `tie_at_top1` | 重排后 top-1 分数是否并列 | 说明名次由破并列规则决定 |
| **`cosine_gap`** | **gold 与最强干扰的 cosine 差** | **说明名次离翻转有多远** |

**两者都是"这个名次有多稳"的量化**，只是量不同（并列 vs 分差）。

**所以新增字段不是新概念，是把已有概念换一个量。**

## 决策 5：本变更只测量，不实施

**继承的原则**：测量可以现在做，实施要等决策。

**本变更做**：
1. 实测噪声边界
2. 定阈值 0.01
3. 登记未来字段与验收
4. 写进报告

**本变更不做**：
1. 不改 `FeatureScores`
2. 不加 `cosine_gap` 字段到产物
3. 不改权重
4. 不实施"稳定 case 子集"验收

**为什么**：那四步是装置变更，需要单独决策（尤其是权重）。

## 风险与取舍

| 风险 | 缓解 |
|---|---|
| 0.01 阈值可能在别的数据上不够 | 它是"实测最大噪声 × 1.6"，换数据要重测 |
| 噪声实测只用了 sample 的 10 个 case | 30 个样本（10 case × 3 候选），足够覆盖夹角范围 |
| 缓存未命中的噪声只测了一次 | 那是"两个独立调用"的差异，不是分布——将来可测多次取上界 |

**最后一条要写进报告**：`0.9971` 是一次测量，不是上界。
真实上界可能更大，而阈值 0.01 留了 1.6 倍余量。

## 不做的事

- **不改产物格式**
- **不改权重**
- **不加 cosine 特征**
- **不造 v3 数据**
