## 决策 1：三张表都要验，不是只补用户点名的那一张

用户只指出了 Scenario 表。实测发现三张表有同一种缺口，**第三张更严重**：

| 表 | 形态 | 之前 |
|---|---|---|
| MUST/SHALL 行表 | 分项错、合计对 | 全绿 |
| Scenario 表 | 分项错、合计对 | 全绿 |
| 要求数表 | **分项之和 54 != 合计 59** | 全绿 |

第三种不是"被合计掩盖"，而是**整张表没人看**。
只按用户建议补 Scenario 表，要求数表会继续错着。

## 决策 2：两条断言，不是三条

| 断言 | 抓什么 | 能被单独违反吗 |
|---|---|---|
| 逐行 == `compute()` | 某行数字写错 | ✅ 改一行 |
| `sum(分项) == 合计` | 少了/多了一行，或合计被手改 | ✅ 删一行 / 改合计 |

**我一开始写了第三条"合计 == `compute()` 总和"，然后发现它永远不红**：

```
若逐行全 == compute():
  sum(分项) == sum(compute 各能力) == compute 总和
若再有 sum(分项) == 合计:
  合计 == compute 总和      <- 必然成立
```

**在前两条都通过的前提下，第三条恒真。** 那是恒真断言，不是判据——
本项目明令禁止"不能被违反的断言"。

**但第三条有独立价值的场景是什么**：当表格**缺少一行**时，
第二条说"分项和 != 合计"。这已经够了。

**所以删掉它**，而不是留着"多一层保护"。多留一条恒真的断言会让
"三条都通过"看起来比"两条都通过"更可靠——那是假的。

## 决策 3：定位表格用表头，不用字符串包含

**我第一版写的是**：

```python
plain = f"| `{cap}` | {expected} |"
bold = f"| `{cap}` | **{expected}** |"
if plain not in section and bold not in section:
```

**它错了两处，都是实测出来的**：

| 错 | 现象 |
|---|---|
| §0.6 里有**两张**两列表 | MUST 表被读成四类表，`conflict-resolution` 显示 35 而不是 9 |
| 加粗写法不统一 | `| **`retrieval-apparatus`** | **30** |` 匹配不到，报"表里找不到 30" |

**改成解析**：先按表头切出那一张表（`section[idx:].split("\n\n")[0]`），
再逐行解析两列单元格，先 `replace("*", "")` 再去反引号。

**顺带解决第三个问题**：`in section` 会让"这个数字出现在表格下方的正文里"
也通过。解析只收表格行。

## 决策 4："不改 `_load_run`" 要写成断言，不是写进文档

上一轮我说"这是待决定的问题"。实测后确认**现在的分工已经是对的**：

| 产物族 | 缺失含义 | 处置 |
|---|---|---|
| `a3-*.json` | 实验没做 | 失败 |
| `v2-*` / `v3-*` | 这代还没数据 | 不适用 |

但"现在是对的"不等于"不会被人改错"。所以加两条**配对**的断言：

- `test_fixed_path_gates_fail_when_artifact_missing`（4 条判失败）
- `test_v3_aware_gates_are_not_applicable_when_zone_empty`（2 条判不适用）

**为什么必须配对**：只写一侧，读者会推出错误的一般化——
只看第一条会以为"所有缺文件都该红"，只看第二条会以为可以给
`_load_run` 加三态。

## 决策 5：`_declared_total` 不能用 `in` 判断

```python
# 错的
assert f"| 合计 | {total} |" in section
```

`| **合计** | **300** |` **包含** `| 合计 | 300 |` 的子串。
所以必须先定位表头，再取"合计"那一行的第二个单元格。

这与上一轮 `test_scenario_count_is_real` 的 scope 修复是同一类问题：
**先切出范围，再判断。**

## Risks / Trade-offs

| 风险 | 缓解 |
|---|---|
| 表格格式变化（列数、表头文字）会让解析失效 | 失效方式是抛 `AssertionError("找不到表头")`，不是静默通过 |
| 新增一张按能力拆分的表而没登记 | 三张表的 scope 用标题锚定；新增表若沿用旧标题会被解析到，若用新标题则需登记 |

## 不做的事

- **不改 `_load_run`**：见决策 4
- **不改 `compute()` 的返回结构**
- **不造 v3 数据**
