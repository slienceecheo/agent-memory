## 决策 1：判据用 `applicable and not passed`，不用 `not passed`

**这是 `main()` 那个 bug 在测试里的同型实例。**

`main()` 已经修了；测试里还留着一份。

**为什么之前没被发现**：`test_every_failing_gate_is_classified` 的断言是

```python
for code in failed:
    assert code in text, f"未通过项 {code} 没在 HANDOFF 里出现"
```

**它检查的是"这个 code 在文档里出现过"**，而 `F20`/`F24` 恰好出现在
我解释"不适用不算失败"的那段文字里——**测试因为一段解释自己的文字而通过**。

## 决策 2：证伪必须双向

**只做单向（删真失败 -> 红）不够**：那只能证明"能抓到 X"，
不能证明"没误抓 Y"。

| 证伪 | 期望 | 实际 |
|---|---|---|
| 删 `F17b`（真失败） | 红 | **红**："未通过项 F17b 没在 HANDOFF 里出现" |
| 删 `F20`（不适用） | 不红 | **不红** |

**双向都过，才说明新判据同时做到"抓得到真失败"与"不误抓不适用"。**

## 决策 3：冻结文件读出来的判定，测试名必须写明装置版本

`test_accepted_failure_actually_fails` 改成
`test_accepted_failure_failed_in_v2_apparatus`。

**"actually" 这个词默认指"现在"**，而它读的是冻结文件（`47e4785-dirty`）。
两者的差异是有意的：

| 来源 | `F20` / `F24` |
|---|---|
| 冻结文件（v2 装置） | `sample` 都通过；`billing` 的 `F24` 失败 |
| 当前 `run_all()`（v3 装置） | 都 `applicable=False` |

**不写清就会被读成"两处矛盾"**，而实际是"装置变了，适用性也变了"。

## 决策 4：`ACCEPTED_FAILURES["F24"]` 的描述补范围

旧描述：`"正确的失败：billing A 轴 SEH@1 = 1.0000"`

**问题**：`sample` 的 `F24` 在冻结文件里是**通过**，旧描述没写清只针对 `billing`。

新描述：`"正确的失败：**billing** A 轴 SEH@1 = 1.0000（sample 上是通过）"`

## 关于"测试读脚本输出"

上一轮说下一轮做。**本变更不做**，理由是范围比预估大：

| 类型 | 例子 | 能否读脚本 |
|---|---|---|
| 单一数字 | `assert "149" in section` | ✅ 容易 |
| 百分比 + 分母 | `assert "1/149 = 0.7%" in section` | ✅ 需格式化模板 |
| **章节结构** | `assert "本节有两个 1.2%" in section` | ❌ **是文案，不是数字** |

**第三类不该读脚本**——它断言的是"必须有这个说明"，不是"这个数是多少"。

所以那个变更要先分类 13 处断言，再决定哪些改成读脚本。
这不该塞进本变更。

## Risks / Trade-offs

| 风险 | 缓解 |
|---|---|
| 新判据可能漏掉某些失败 | 双向证伪：真失败仍被抓到 |
| 改名会破坏既有引用 | 全仓库 grep 过，无外部引用 |

## 不做的事

- **不改 `main()` / `--json`**：上一轮已完成
- **不改 `ACCEPTED_FAILURES` 的内容**：只补描述范围
- **不做"测试读脚本输出"**：见上
