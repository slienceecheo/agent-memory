## 决策 1：第五种形态与前四种的区别

**前四种的断言本身有问题**：

| # | 问题在哪 |
|---|---|
| 1 永远绿 | 断言没有判别力 |
| 2 永远红 | 断言必然失败 |
| 3 误报 | 名字与实现不符 |
| 4 注释与实现不符 | 注释撒谎 |

**第五种的断言完全正确**——它在自己的范围内没有任何缺陷。

**但它只覆盖了该覆盖范围的一部分**，而名字和位置让人以为覆盖了全部。

**这决定了发现方式**：

| 形态 | 发现方式 |
|---|---|
| 1–2 | 看断言能否被违反 |
| 3 | 看红的**原因** |
| 4 | 看值与样本量是否自洽 |
| **5** | **删掉链路的另一层** |

## 决策 2：为什么必须检查"不对称"

**"那一行还在"是最弱的判据**：
把表格里「绿」改成「红」，行还在，但它表达的事实变了。

**所以断言检查的是两列的关系**：

```python
assert "绿" in adjacency_row[0] and "红" in adjacency_row[0]
```

**实测**：

| 构造 | 期望 |
|---|---|
| 删掉 adjacency 行 | 红（行不在） |
| 把「绿」改成「红」 | **红（不对称消失）** |

**第二条是本变更的核心**：它证明断言抓的是"行为与源码的差异"，
而不只是"那一行还在"。

## 决策 3：标题里的数字也要断言

**`### 坏断言的四种形态` 这个标题里的"四"本身就是一个没有守着的数字。**

它和我刚修的 `359` 是同一个形态：
**数字写死在文字里，而断言不依赖它。**

**所以本变更给它加了断言**：

```python
m = re.search(r"### 坏断言的(.{1,8}?)形态", section)
declared = next((zh[c] for c in title_part if c in zh), None)
assert declared == 5
```

**这是第五条规则的自我应用**：
清单记录"覆盖范围被高估"，而它自己的标题也曾高估。

## 决策 4：`CAPABILITIES` 的两个断言

**为什么在两处断言**：

| 位置 | 作用 |
|---|---|
| `test_spec_normative_words.py::test_capabilities_list_covers_all_existing_specs` | 在"使用者"旁边 |
| `test_assertion_forms.py::test_capabilities_covers_all_specs` | 在"形态记录"旁边 |

**若只在一处**，删掉那一条就没了。**两处各自独立**，删一个另一个还在。

**为什么值得重复**：`CAPABILITIES` 漂移过一次没人发现，
因为当时**唯一的覆盖检查不存在**。代价很小。

## 决策 5：补齐后比例仍然通过，但含义变了

| 版本 | 分母 | 比例 |
|---|---|---|
| 补齐前 | 365（5 能力） | 185/365 = **50.7%** |
| 补齐后 | 380（6 能力） | 185/380 = **48.7%** |

**两者都在 `[0.4, 0.7]` 内**，所以断言没红。
但**含义不同**：补齐前的 50.7% 是"5 个能力里约半数"，
补齐后才是"全仓库约半数"。

**这解释了为什么之前有人以为比例"刚好跌破 50%"**——
那是用旧分母算的。

## 风险与取舍

| 风险 | 缓解 |
|---|---|
| 标题断言依赖中文数字映射 | 只映射 1–6，超出会 `declared = None` 而红 |
| 两处 `CAPABILITIES` 断言可能漂移 | 它们都比对同一个 `openspec/specs/`，不会互相漂 |
| `[0.4, 0.7]` 区间可能过宽 | 它比"卡整数阈值"稳；且值变了会进失败消息 |

- **不删 `status`**（下个变更）
