## 决策 1：选"新建变更 + 保留旧结论"，不选静默改

**三个选项**：

| 方案 | 问题 |
|---|---|
| B：只改代码，报告加一行订正 | 正文仍是错的，而读者会相信有公式的表格 |
| C：回滚上一个归档 | 会删掉"我当时怎么想的"，下一个人会重犯 |
| **A：新建变更，正文改对 + 保留订正段** | 留下"刚归档就推翻"的记录，但那正是应留的 |

**为什么 A 的代价可接受**：这个项目一直保留错误的原因
（比如 `3b.5` 那条"后续更正"）。删掉它，下一个人只能看到正确答案，
不知道错的那个曾经看起来多么合理。

## 决策 2：订正段必须紧邻错值，并写明"为什么没被发现"

**只写"这里错了"不够**，因为：

1. 读者可能只看表格
2. 下一个人不知道该怎么防

**所以订正段包含三件事**：

| 内容 | 作用 |
|---|---|
| 旧值（0.0079）与旧结论（"显著"） | 让读者知道哪个数被撤销了 |
| 错因（C 组混入对照组） | 让读者能判断影响范围 |
| **为什么证伪没发现** | 让下一个人知道这类错误的检测边界 |

**第三件最重要**。本次的答案是：

> 证伪时断言确实红了，但红是因为**代码算出了显著 p**，
> 不是因为**注释被验证**。证伪检查代码行为，不检查注释。

## 决策 3：统计断言改成断言具体值

**旧**：

```python
assert measured["sample"]["p"] < 0.05
```

**问题**：这是"显著"的方向断言。修正后 `sample` 的 p = 0.3333，
这条会失败——但**不能简单翻成 `> 0.05`**，因为 `p = 0.99` 也会通过。

**新**：

```python
assert measured["sample"]["p"] == pytest.approx(0.3333, abs=1e-3)
assert measured["billing"]["p"] == pytest.approx(0.7778, abs=1e-3)
```

**为什么可以精确断言**：置换检验是**精确检验**（穷举全部组合），
`p = k / 组合数` 是离散确定的，不依赖随机种子。

**这也是为什么 `p=0.0079` 可疑**：`sample` 只有 `C(6,5)=6` 种组合，
可能的 p 值只有 `1/6 = 0.1667`、`2/6 = 0.3333`、… 这些离散值。
**0.0079 根本不在可能取值里**——它来自 `C(10,5)=252`，也就是 C 组混入后的组合数。

**发现路径就是这个**：p 值与 n 的离散性不符。

## 决策 4：`billing-c2` 和 `billing-a3` 的解释都要撤

**`billing-c2`**：排序空间 = 1。
query「税务申报是按什么分的？」, gold「华北的客户在北京税局申报」
共享 bigram 只有「申报」。但**空间 = 1，它没有竞争对手**。
所以"bigram 抓不到但命中了"这个说法对它不成立——它命中是因为只有它一个候选。

**`billing-a3`**：空间 = 2，共享 bigram 是 **「抬头」、「，抬」**。
query：「德国那边的账怎么开，**抬头**还要写什么？」
gold：「会议纪要里定的：欧洲客户走欧元发票，**抬头**必须填 VAT 号」

**它是"抬头"的字面命中，不是"德国↔欧洲"的语义映射。**
`lexical` 是中文 bigram + BM25，不做跨语种语义。

**所以我上一轮那条"跨语种语义相关"的解释是编的**，不是测出来的。

## 决策 5：`low_overlap_top1` 从"能力描述"改成"机制描述"

**旧**：3 条低重叠 top-1，理由是"语义相关"。

**新**：

| case | 空间 | 机制 |
|---|---|---|
| `billing-c1` | 2 | 二选一，靠「发票」 |
| `billing-a3` | 2 | 二选一，靠「抬头」 |
| ~~`billing-c2`~~ | **1** | **无竞争**，不属于"低重叠却命中"的证据 |

**改成机制描述**：这 3 条里 2 条是"二选一"，1 条是"无竞争"。
**不是"lexical 能做语义匹配"。**

## 决策 6：排序空间必须与池大小分开

**这是用户发现的量，比池大小更根本。**

| subject | 池大小 | lexical 排序空间 |
|---|---|---|
| `sample` | 12–14 | **0–2** |
| `billing` | 9 | **0–4** |

**随机基线的分母必须是排序空间**：

```
sample   1/空间 平均 = 0.6667      1/池 = 0.0833
billing  1/空间 平均 = 0.6111      1/池 = 0.1111
```

**用 1/池会把随机基线低估 8 倍**，于是"lexical 0.83 vs 随机 0.08"
看起来增益 +0.75，而实际是 **+0.17**。

**F24 的随机基线用的是派生 within 的池大小**，那是另一套口径
（它算的是"整个池里随机选一个"，不是"lexical 召回后重排"）。
**两套口径都对，但回答的问题不同**，不能混用。

## Risks / Trade-offs

| 风险 | 缓解 |
|---|---|
| 保留错误结论会让读者误读 | 订正段紧邻错值，且明确说"这是错的" |
| 精确 p 断言可能因数据微调而频繁红 | 那正是目的：它逼人重算而不是忽略 |
| 排序空间的"1/空间"基线可能被认为过于悲观 | 它与"池大小"基线并列给出，读者可判断 |

## 不做的事

- **不改 `F24` 的基线口径**（它算的是另一件事，见决策 6）
- **不测 cosine**
- **不改融合、不加特征**
- **不造 v3 数据**
