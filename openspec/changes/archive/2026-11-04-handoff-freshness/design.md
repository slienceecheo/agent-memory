## 决策 1：日期断言用"最后一次归档日期"，不用"今天"

**为什么不用 `date.today()`**：那会让测试在**跨日**时红，
而红的原因与文档无关。归档目录名里已有日期，那是**事实**；
"今天"是**运行时刻**。前者可复算，后者不可。

```python
更新日期 == max(openspec/changes/archive/ 下目录名的 YYYY-MM-DD 前缀)
```

## 决策 2：另加一条"不得是未来日期"

**单独一条，不是合并进上一条**。

理由：若有人把日期写成 `2099-01-01`，上面那条会**一直红**
（归档日期追不上 2099），于是他可能去改判据。
**先用这条拦住"写未来日期"这个错误做法**，让上面那条的红指向真正的原因。

## 决策 3：不改 `test_accepted_failures` 的判据

**这是更正上一轮的归类错误。**

上一轮我把两处归为一类（都"用旧判据"），但实测：

```
v2-sample-gates.json   checks=27  含 applicable=False   键=[code, detail, passed, title]
```

**冻结文件没有 `applicable` 字段**，它由 v2 装置产出，那时只有两态。
所以 `not c["passed"]` **在那份文件上是正确的**。

**如果改成 `applicable and not passed`，会 `KeyError`**——或者更糟，
如果实现写成 `c.get("applicable", True)`，缺失会被静默当成 `True`。

**三态判据只适用于当前 `run_all()` 的返回值。**

## 决策 4：`ACCEPTED_FAILURES["F24"]` 写全两个 subject

**因为它同时表达两件事**，而原来只有一行只说了一件：

| subject | 冻结文件里的 `F24` |
|---|---|
| `billing` | **失败**（SEH@1 = 1.0000 满分） |
| `sample` | **通过**（0.9000） |

只写 billing 会让读者以为两边都失败。

## 决策 5：lock 说明写进「环境与纪律」，不写进测试

**它不是可自动检查的**：lock 的存在只是"归档中途失败"的遗迹，
而测试无法判断"这次失败是否该删 lock"。

**所以只做一件事**：让人下次遇到时不用重新推理。

## Risks / Trade-offs

| 风险 | 缓解 |
|---|---|
| 日期断言的"最后一次归档"依赖目录名格式 | 格式已固定为 `YYYY-MM-DD-<name>`，且有正则校验 |
| 每次归档都要改日期 | 那是正确的：日期本来就是"最后更新"标记 |
| lock 说明可能过期 | 它描述的是工具行为，不随本项目变 |
