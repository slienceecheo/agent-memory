## Why

上一轮交付的 `axis_baseline_derived` 与 `F24` 的 v3 分支有三处缺口，其中两处会让判据静默失效。

**第一条：空组返回 `0.0`，把"没有数据"伪装成"基线是 0"。**

```python
axis: (sum(values) / len(values) if values else 0.0)     # <- 空组
```

实测 `billing` 的 `relation_cross` 是空组（三个 relation 全多分支，
12 条派生全落在 within），旧实现返回 **`0.0`**。

`0.0` 作为基线意味着"随机命中率是 0"。**它的实际后果是让判据变宽松**：
判据是 `if ratio <= baseline: 红`，而 `baseline=0.0` 时只有 `ratio=0` 才红——
**任何 `ratio > 0` 的值都会通过**。

所以空轴会被伪装成**最容易达标**的轴：报告按轴聚合时，cross 轴会显示
"0 条不达标"，而它根本没有查询。

（上一版 proposal 写的是"任何实测值都报红"，方向写反了——
`0.0` 让判据变松，不是变严。危险的方式不同，但同样会让"没有数据"看起来正常。）

**第二条：v3 的结果侧只有下限，抓不到"数据太简单"。**

上一轮把 v3 判据定为 `ratio > baseline`。这抓的是"排序比随机差"，
但抓不到"数据太容易"——

v3 数据要求"每 subject 至少一个单值 relation"，而单值 relation 意味着
池可能很小（`n_competitors=1` -> 池 2），于是 `ratio` 容易满分。

**只设下限会放行"数据太简单"。**

**第三条：v3 的数据侧是恒真的，但没人写明。**

派生 within 的池大小 `= n_competitors + 1 >= 2`，所以基线最大 `1/2 = 0.5`，
**永远小于 `0.9999`**。实测 `sample` / `billing` 的理论最大基线都是 `1/3`。

所以 `if baseline_seh1 >= ceiling` 在 v3 下**从不成立**——
读者会以为"两段都在验"，而实际只有结果侧在起作用。

## What Changes

**1. 空组返回 `None`，不返回 `0.0`**

```python
axis: (sum(values) / len(values) if values else None)
```

返回类型变成 `dict[str, float | None]`，**调用方必须显式处理 `None`**。
这比"返回 0.0 然后等下一个人踩"安全。

**2. v3 的结果侧判据加回上限**

| 档 | 判据 | 违反形式 |
|---|---|---|
| 下限 | `ratio > baseline` | 排序比随机还差 |
| **上限** | **`ratio < ceiling`** | **数据太简单**（池太小，随便排都对） |

**上限在 v3 下的语义是"数据难度"，不是"装置语义"**：
v2 里满分意味着"指标测不到区分能力"（装置与数据都有关）；
v3 里满分只说明"这份数据太容易"（数据问题）。所以 `0.9999` 仍有效。

**3. 写明 v3 的数据侧是恒真的**

保留该判据（它防的是"池大小退化成 1"这个形状退化），
但 MUST 在代码注释与 spec 里写明：v3 下它恒真，真正有判别力的是结果侧。

## Impact

- 代码：`evals/metrics/v2_baselines.py`（返回类型 `float | None`）、
  `evals/tools/check_v2_dataset.py`（`F24` 的 v3 分支：`None` 防护 + 上限）
- 测试：`test_derived_axis_baseline.py`（空组 `None`）、
  `test_f24_derived_axis.py`（上限、数据侧恒真登记）
- 数据 / 结果文件：**无**
- **`run_all()` 数字不变**：`sample 19/27`、`billing 23/27`
  （`F24` 在真实 v2 产物上仍不适用）

## 验收

| # | 判据 | 可被违反的形式 |
|---|---|---|
| 1 | `billing` 的 `relation_cross` 是 `None` | 返回 `0.0` 会伪装成"基线是 0" |
| 2 | `sample` 的 `relation_cross` 是 `0.0833`（有对象时必须是数值） | 反向确认 `None` 不是普遍行为 |
| 3 | v3 下满分（`ratio=1.0`）必须**红** | 只设下限会放行"数据太简单" |
| 4 | v3 下 `ratio=0.5`（`baseline < 0.5 < ceiling`）必须**绿** | 数据侧与下限的联合验证 |
| 5 | **v3 数据侧恒真必须被登记** | 断言"理论最大基线 < 0.9999"，若池退化成 1 则红 |

**验收 1 与 3 是本变更的两个核心**：前者防"空组伪装成 0"，后者防"只设下限"。
