## 决策 1：宽区间保留，另加精确分母断言

**用户建议"保留宽区间 + 加分母断言"，我同意。**

**两者的分工**：

| 判据 | 抓什么 | 能被什么违反 |
|---|---|---|
| `0.4 <= ratio <= 0.7` | **剧变** | 统一规范词（比例骤降）/ 删光（接近 1） |
| `total == sum(各能力 Scenario)` | **漂移** | 漏一个能力（分母差 15，比例变 4 个百分点） |

**为什么不能用一条替换另一条**：

- 只留区间 -> 漏项永远不红（实测三次都绿）
- 只留分母 -> "有人统一了所有规范词"这类剧变不红

**所以两条都要。**

## 决策 2：分母断言写在哪

**写在同一个测试内，作为前置断言**：

```python
def test_scenarios_are_not_required_to_carry_normative_words():
    total = 0
    ...
    # 分母必须等于各能力之和（本循环累加出来的就是它）
    assert total == sum(len(_scenarios(...)) for c in CAPABILITIES)
```

**这个写法看起来是恒真**（`total` 就是循环累加的），所以要换个写法：

```python
expected = sum(
    len(_scenarios((SPECS / c / "spec.md").read_text(encoding="utf-8")))
    for c in CAPABILITIES
)
assert total == expected
```

**它仍然是同一个量**——但**它抓的是"循环漏了某个能力"**。

**更好的写法：让分母从 `CAPABILITIES` 直接算出来，再与循环结果比。**

**为什么这有价值**：若有人给循环加了 `if capability != "x": continue` 之类的过滤，
`total` 会小于 `expected`，断言红。

## 决策 3：不对称检查改成比较单元格

**用户的判据更好，我采纳。**

```python
cells = [c.strip() for c in adjacency_row[0].strip("|").split("|")]
assert cells[1] != cells[2]
```

**但要处理表格的加粗**：HANDOFF 里是 `| **绿** | **红** |`，
单元格带 `**`。所以要先去掉：

```python
def _cells(row: str) -> list[str]:
    return [c.strip().replace("*", "").strip() for c in row.strip("|").split("|")]
```

**验证两种措辞都成立**：

| 表格内容 | `cells[1] != cells[2]` |
|---|---|
| `**绿**` / `**红**` | True ✅ |
| `通过` / `失败` | True ✅ |
| `**红**` / `**红**` | False（断言红）✅ |

## 决策 4：`359` 的处理

**用户给了两个选项：带时间标记 / 删掉。选带时间标记。**

**为什么不删**：它记录了一个真实的历史状态
（"曾用漏项的分母算过一次"），删掉就丢了"为什么会误判"的线索。

**为什么必须标时间**：不标的话，读者会以为它是当前值——
而当前是 380。

**写成**：

```
> 359 是第 26 次归档时的值（当时 evaluation-harness 172，现在 183）。
> 本数字只作历史记录，判据不依赖它。
```

**最后一句的判据价值**：它说明"改不改它都不影响测试"——
这样读者不会花时间去同步它。

## 风险与取舍

| 风险 | 缓解 |
|---|---|
| 分母断言可能与循环同源（恒真） | 让 `expected` 走独立路径（`sum` 生成器），不是复用循环变量 |
| 单元格比较可能因列数变化而失效 | 先断言 `len(cells) == 4`（表格有一列是"删掉什么"） |
| 时间标记会随归档过期 | 它本来就该过期——那是"历史记录"的定义 |

## 不做的事

- **不起 `cosine-as-sort-feature`**（本变更只清残留）
- **不改宽区间**
- **不改 `CAPABILITIES`**
