## ADDED Requirements

### Requirement: 比例的分母必须精确，不能用宽区间代替

当测试用"分子/分母"的比例做断言时，
MUST 同时断言分母等于它声称的来源之和，MUST NOT 只用宽区间容纳。

#### Scenario: 宽区间对"分母漏项"无感知

- **WHEN** 分母漏掉了 `CAPABILITIES` 里的一个能力
- **THEN** 比例会变化 1–2 个百分点
- **AND** 宽区间 `[0.4, 0.7]` **不会红**

**实测轨迹**：

| 归档 | 分母 | 比例 | 在 `[0.4, 0.7]` 内 |
|---|---|---|---|
| 第二十六次 | 365（漏 `retrieval-apparatus`） | 50.7% | ✅ **错值也绿** |
| 第二十七次 | 365（仍漏） | 49.9% | ✅ **错值也绿** |
| 第二十八次 | **380**（补齐） | **48.05%** | ✅ |

**前两行的分母是错的**，而区间全程绿。

#### Scenario: 分母断言必须是精确等式

- **WHEN** 断言比例的分母
- **THEN** MUST 写成 `total == sum(每个能力的 Scenario 数)`
- **AND** MUST NOT 写成 `0.4 <= ratio <= 0.7`

**两者分工不同**：

| 判据 | 抓什么 |
|---|---|
| 宽区间 | **剧变**（统一规范词 / 删光规范词） |
| **分母等式** | **漂移**（漏一个能力） |

**所以两条都要留**，不是用一条替换另一条。

### Requirement: 文档里的历史数字必须带时间标记

当文档（含 docstring）引用一个"会随归档变化"的数字时，
MUST 标明它是哪一次归档的值，MUST NOT 让它看起来像当前值。

#### Scenario: 无时间标记的历史数字会被当成当前值

- **WHEN** docstring 里写「比例跌破 50%（179/359）」
- **THEN** 下一个读者会以为 359 是当前分母
- **AND** 而当前是 380

**实测**：`359` 曾在不同时期同时是
`must_lines` 与"5 个能力的 Scenario 和"——**同一个数字两种含义**。

**所以必须写成**：

```
> 359 是第 26 次归档时的值（当时 evaluation-harness 172，现在 183）。
> 本数字只作历史记录，判据不依赖它。
```

**最后一句是关键**：它说明"这个数字变了也不影响判据"，
否则读者会去改它。

### Requirement: 单元格比较不得依赖具体措辞

当断言"表格两列的内容不同"时，
MUST 比较单元格的值本身，MUST NOT 依赖某个具体词（如「绿」「红」）。

#### Scenario: 措辞变了，判据就不该失效

- **WHEN** 表格从「绿/红」改成「通过/失败」
- **THEN** "两列不同"这个事实仍然成立
- **AND** 断言 MUST 仍然有效

**实测反例**：

```python
assert "绿" in row and "红" in row   # 依赖措辞
```

改成：

```python
cells = [c.strip() for c in row.strip("|").split("|")]
assert cells[1] != cells[2]          # 只依赖"不同"
```

**为什么这样更强**：它抓的是**语义关系**（行为与源码结论不同），
而不是**排版形式**（用了哪两个字）。
