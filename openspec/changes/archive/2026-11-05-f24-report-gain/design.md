## 决策 1：报差值，不设区间

**备选 A：定 `0.5 < ratio < 0.9`**

不可行。它会把"造数据"变成"凑指标"：
ratio 落不进区间时，最省事的做法是调数据难度，而不是如实报告。

**备选 B：先造出来再看**

也不可行。ratio 落进哪里都接受时，上限 `0.9999` 在数据上就没有约束力——
它可以永远不红。

**选 C：只报 `ratio - baseline`**

| 差 | 结论 |
|---|---|
| ≈ 0 | 这份数据上排序没有增益 |
| 明显 > 0 | 有增益，数值就是增益大小 |
| < 0 | 排序比随机还差 |

**它不判"落在哪"，只陈述"增益多少"**，所以不诱导改数据。

## 决策 2：失败了也报差值

"太容易"时 detail 是：

```
[数据侧通过] 派生 within 基线 0.2778；
[结果侧失败] 实测 12/12=1.0000 vs 派生 within 基线 0.2778（差 +0.7222；...）；
满分说明这份数据太容易（池太小，随便排都对）
```

**`+0.7222` 是"有多容易"的量化**。只在通过时报，红的时候读者要手算。

## 决策 3：v2 分支不改

v2 的判据是"不满分"，**没有 baseline 可对照**（v2 的基线判据在数据侧，
不在结果侧）。所以 v2 的 detail 保持原样。

**这会不会让两条分支不一致**：会，而且应该不一致——
它们的判据本来就不同（v3 判"高于基线"，v2 判"不满分"）。

## 决策 4：`test_f24_has_no_target_range` 读源码文本

```python
body = src[start:end]
for marker in ("target_low", "target_high", "TARGET_", "target_range"):
    assert marker not in body
```

**为什么不用行为断言**："不得引入区间"是一个**结构约束**，不是行为。
有区间的实现照样能通过"报差值"的断言（它只是多判了一条），
所以行为断言抓不到它。

**局限**：改函数名会让 `start` 找不到。
但 `assert start >= 0` 会先红，不会静默通过。

## 关于 `+.4f` 而不是 `.4f`

```python
f"{gain:+.4f}"   # +0.2222 / -0.1944
f"{gain:.4f}"    # 0.2222  / 0.1944     <- 丢符号
```

**丢符号的后果**：`ratio < baseline`（排序比随机差）与
`ratio > baseline`（有增益）都写成 `差 0.1944`——两条相反的结论同一个句子。

`test_f24_reports_gain_when_below_baseline` 里额外断言
`f"{gain:+.4f}".startswith("-")`，防的正是这个。

## Risks / Trade-offs

| 风险 | 缓解 |
|---|---|
| 差值让 detail 变长 | 一行内可读，且 `--json` 里有结构化字段 |
| 源码文本断言太脆 | 只查 4 个标记词，不断言整句 |
| 有人日后加区间 | `test_f24_has_no_target_range` 会红 |

## 不做的事

- **不造 v3 数据**
- **不改 `F24` 的判据**（仍是 `baseline < ratio < 0.9999`）
- **不动 v2 分支的 detail**
