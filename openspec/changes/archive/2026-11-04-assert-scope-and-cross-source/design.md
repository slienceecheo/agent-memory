## 决策 1：scope 用"切节"而不是"精确匹配整行"

**备选：把断言写成 `assert f"| **合计** | **{total}** |" in text` 且要求唯一**。

不可行：三处格式完全相同，无法从字符串本身区分。

**所以切节**：

```python
section = text.split("真正该看的数字：")[1].split("\n### ")[0]
section = text.split("### 0.6 自动检查的边界")[1].split("### 0.7")[0]
```

**切分锚点选标题而不是行号**：行号每次归档都变，标题稳定。

## 决策 2：交叉断言的判据是"同源"，不是"数值相等"

`four_way.has_fn.n` 与 `MANUAL_SYMBOL_EXISTS_ROWS` 的**定义**是同一个量：
"有函数名的行" = "`exists` 检查能覆盖的行"。

**但它们的来源不同**（一个是扫描，一个是手写常量），所以必须交叉断言。

**为什么不干脆让 `three_layer.symbol_exists.numerator = four_way.has_fn.n`**：

那会让"符号存在"不再是独立的人工结论。
**它是人工判断**（"`substring_exact_match` 那一条 exists 有意义"），
而不是"扫出来的 1 条"——两者现在数值相同，但定义不同。

**交叉断言的作用**：当它们分离时报警，而不是强行合并。

## 决策 3：`test_recount_script_matches_reality` 用 `compute()` 而不是 `main()`

| 写法 | 问题 |
|---|---|
| `assert mod.main() == 0` | 打印污染；只证明"没抛异常" |
| `assert compute()["scenarios"] > 0` | 无输出；证明"算出了东西" |

**加一条内部一致性**：四类之和 == 总数。那能抓"分组有重叠或遗漏"。

## 决策 4：证伪必须构造"数字相等"的场景

**第一次证伪失败了**，因为我只把 Scenario 表改成 214（与 MUST 相同），
却没让 `compute()` 的真值也相等——于是全文找不到 287，必然红。
**那不是顶替，是"确实没有这个数"。**

**第二次也失败**：我 patch 了 `rs.compute`，但测试里是
`from ... import compute`，而我只验证了 patch 生效、没验证
**文档的 MUST 表也要写 220**。

**第三次成功**：同时满足三个条件
1. `compute()` 返回 scenarios=220, must_lines=220
2. 文档 Scenario 表写 219（错）
3. 文档 MUST 表写 220（对）

于是全文有 `| **合计** | **220** |`，断言通过——**顶替发生**。

**教训**：证伪"两个值互相顶替"时，必须让**两个值真的相等**，
而不只是让一个值写错。

## 关于"patch 模块属性无效"这个坑（第三次踩）

| # | 场景 | 原因 |
|---|---|---|
| 1 | 改 `mod.ROOT` | `HANDOFF` 是模块常量，import 时固定 |
| 2 | 改 `rs.compute` | 我以为无效，实际有效——但文档没同步改 |
| 3 | 改 `mod.HANDOFF` | 有效（`_text()` 读模块全局） |

**每次都要先验证 patch 真的生效**，而不是假设。

## Risks / Trade-offs

| 风险 | 缓解 |
|---|---|
| 切节锚点（标题）若改，scope 会切错 | 锚点是 `### 0.6 自动检查的边界` 与 `真正该看的数字：`，都是稳定标题 |
| 交叉断言会让"改常量"变成两步 | 那正是目的：两处同源必须同步 |
