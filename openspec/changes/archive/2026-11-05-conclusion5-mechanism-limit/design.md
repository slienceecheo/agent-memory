## 决策 1：写"机制未区分"，不测 cosine 分布

**备选 A：现在测 cosine 分布。**

**不可行**：现有 15 份冻结产物都没有记录 cosine 分
（`features_by_tag` 为空，无 `cos`/`similar` 字段）。
测出来的数字无法从产物复算，所以不能进带复算命令的报告。

**备选 B：改产物格式，让它记录 cosine。**

**违反"v2 产物冻结"**：要么改现有 15 份文件的内容，要么在顶层新增文件
（48 → 49，破坏分区约束）。

**选 C：把"未区分"写进报告，作为显式边界。**

**为什么它比测分布更有价值**：它把"未知"显式化。下一个人不会以为
结论 5 已经解释了原因，从而直接去改融合——而真正的原因可能是 cosine 排序。

## 决策 2：把 cosine 归入 v3 装置变更，不是报告变更

若将来要测 cosine 排序质量，正确的顺序是：

1. 先决定"cosine 要不要成为正式特征"
2. 若是，则它属于 **v3 装置变更**
3. 那时才让产物记录 cosine，且记录在 `results/v3/` 里，不动 v2 的 48 份
4. 然后用 v3 产物复算分布

**先测分布再决定加不加**是错的顺序：测出的数字只能当"探索性证据"，
不能进报告。这与本项目"文档数字必须可复算"的纪律冲突。

## 决策 3：拆开"读产物"与"读文档"两条断言

**这是我这一轮踩到的坑。**

我写了一条：

```python
def test_report_documents_vector_returns_whole_pool() -> None:
    """..."""
    for name in ("a3-...json", "v2-billing-...json"):
        path = ROOT / "results" / name
        ...
```

**名字说"report documents"，但函数体只读 `results/`，一个字都没读文档。**

**后果**：删掉报告里"返回了整个池"那句话，这条断言不会红。

**更糟的是它伪装得像通过了**：证伪时它确实红过一次，但那是因为临时目录里
产物文件缺失（`缺少产物 a3-...json`），**与文档无关**。我差点把它当成
"证伪成功"。

**正确做法**：拆成两条。

| 断言 | 读什么 |
|---|---|
| `test_product_shows_vector_returns_whole_pool` | **只读产物** |
| `test_report_documents_vector_returns_whole_pool` | **只读文档** |

**验证它们真的分开**：

| 构造 | 文档断言 | 产物断言 |
|---|---|---|
| 删掉文档那句话 | **红** | 绿 |
| 改产物一个值 | 绿 | **红** |

**这与"恒真断言"是同一族的不同形态**：
恒真是"永远绿"，这个是"名字覆盖了，实现没覆盖"。
两者都无法靠读实现发现，只能靠"构造一个反例，看它红在哪"。

## 决策 4：池大小是 {9, 14}，不是 {9, 12}

用户的说法是"sample 池 12 / billing 池 9"。实测三路产物：

| 产物 | 池大小 |
|---|---|
| `a3-lexical-vector-adjacency.json` | **14** |
| `v2-billing-lexical-vector-adjacency.json` | **9** |

`sample` 的池是 14（33 条 case 有 gold，池 14）。12 可能是把
`ledger-q11/q12` 的 `n_competitors=0` 那种边界 case 混进来了。

**另外**：`v2-sample-lexical-vector-adjacency.json` **不存在**，
`sample` 只有冻结的 `a3-*.json`。所以 §6.1 的 sample 数字来自现场重跑。
