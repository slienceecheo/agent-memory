## 决策 1：常量回答"当前是哪一代"，比较回答"这份文件属不属于它"

**上一轮的错误是把两个问题压成了一个。**

| 问题 | 上一轮的做法 | 正确做法 |
|---|---|---|
| 当前代码是哪一代？ | `CURRENT_APPARATUS` 常量 ✅ | 同左 |
| 这份文件能不能用？ | **也只看常量** ❌ | **常量 vs 签名比较** |

```python
# 错的：常量在进程内恒定，条件恒真
if CURRENT_APPARATUS == "v3":
    return _not_applicable(...)

# 对的：两者比较
if CURRENT_APPARATUS != signature:
    return _not_applicable(...)
```

**为什么不能"改成只看签名"**：签名回答"这东西是谁产的"，
不能用来推"当前代码是哪一代"。那样会让"读到旧文件"变成"以为自己在用旧装置"。

**所以两条都要**：常量定"我是谁"，比较定"它是不是我的"。

## 决策 2：`F20` 在 v3 下不是"不适用"，而是换了一条期望值

**上一轮**：v3 -> 不适用。这等于**放弃一条断言**。

**本变更**：v3 下执行，断言 `drop == 0`。

| 装置 | 判据 | 违反形式 |
|---|---|---|
| v2 | `drop >= 阈值` | 条件没贡献 |
| **v3** | **`drop == 0`** | **`condition` 又回到了加权里** |

**为什么 `drop == 0` 是有意义的断言**：它抓的是"BREAKING 被回退"。
若有人把 `condition` 权重加回去，`with` 与 `without` 的名次就会不同，
`drop` 不再为 0，门禁立刻红。

**而"永久不适用"抓不到任何东西**——它只是把这个测量关掉了。

实测 v3 下 `drop = 0.0000`（with/without 逐条名次完全相同），所以新判据当前通过。

## 决策 3：`F24` 仍保持"不适用"

它与 `F20` 不同：**阈值语义真的反转了**，而不是"期望值变了"。

| 配置 | A 轴 SEH@1 | `< 0.9999` 的含义 |
|---|---|---|
| v2 三路 | 1.0000 | 满分 = 测不到区分能力（坏） |
| v3 单路 | 0.8333 | 低分 = 排序退化（坏） |

同一个阈值在两种装置下**绿/红的意义相反**，所以不能在 v3 下沿用。

**v3 版本的新判据**（如"A 轴 SEH@1 不得低于随机基线"）需要 v3 数据才能定，
不在本变更范围。所以 `F24` 暂时保留"不适用"——**这是有意的，不是遗漏**。

## 决策 4：验收必须有"退回旧实现就变红"的一条

**上一轮的验收 1-4 全部能通过，而 `apparatus_signature` 仍未接进判断。**
这正是本变更存在的理由。

所以新增验收 5：把 `F20` 改回 `if CURRENT_APPARATUS == "v3"`，
`test_f20_actually_reads_the_signature` MUST 变红。

**已证伪**：

```
缺陷版（只看常量）跑新测试
  -> FAILED test_f20_actually_reads_the_signature
  -> "同装置的文件却判'不适用'——说明判断只看常量，
      apparatus_signature 没有接进来。"
```

## 决策 5：常量自检必须比较"常量 vs 现实"

**旧写法**（同义反复）：

```python
assert CURRENT_APPARATUS == "v3"
```

**新写法**：

```python
produced = apparatus_signature({"per_case": result["per_case"]})
assert CURRENT_APPARATUS == produced
```

**旧写法抓不到什么**：有人把 `evaluate()` 的 `features` 改成 `feature_scores`
但忘了改常量——旧写法仍绿，而所有跨装置判断失效。
新写法会红，并指出"常量说 v3，但 evaluate 产出的是 unknown"。

## Risks / Trade-offs

| 风险 | 缓解 |
|---|---|
| `F20` 在 v3 下的新判据可能与旧行为冲突 | 实测 v3 `drop=0.0000`，新判据通过；旧数据仍走 v2 分支 |
| `F24` 的 v3 判据缺位 | 显式登记为"不在本变更范围"，不是遗漏 |
| 常量与现实脱节 | 验收 4 用 `evaluate()` 的真实产物比对 |

## 不做的事

- **不给 `F24` 造 v3 判据**：需要 v3 数据
- **不跑 v3 数据**：验收全用 `tmp_path` 假文件与现有 v2 文件
- **不改 `L6b`/`L8`/`L6c`/`F19b`**：它们不依赖装置，上一轮已正确处理
