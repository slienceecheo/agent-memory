## 决策 1：只自动化 A 类，B 类显式标注"人工"

**这是本变更唯一重要的判断。**

一刀切的诱惑是"把全部 13 处断言改成读脚本"。但那会**创造一种假象**：

```python
# 看起来自动，实际一半手写
assert f"{stats['three_layer']['symbol_exists']['numerator']}/{total} = ..." in section
#                ^^^^^^^^ 这个 numerator 是 MANUAL_SYMBOL_EXISTS_ROWS = 1
```

**测试会绿，而它验证的"1"是人填的**。

**所以 B 类的分子必须显式命名**，让"这是人工结论"在代码里可见，
而不是藏在 f-string 的一个 `{1}` 里。

## 决策 2：`compute(root=...)` 的 root 必须是参数

**这是本项目踩过至少两次的坑**：

| 位置 | 现象 |
|---|---|
| `HANDOFF = ROOT / "docs" / "HANDOFF.md"` | 模块级常量，改 `mod.ROOT` 无效 |
| `_v3_files()` 用 `RESULTS` | skip 条件依赖真实目录而非传入目录 |

**模块常量在 import 时固定**，测试改不动。所以 `compute(root=None)`。

## 决策 3：测试判据改成"文档 == 脚本"，不是"文档 == 字面量"

**旧结构有两个真相来源**：

```
spec  ->  算出的数  ->  HANDOFF
                        ^
              测试断言这个字面量
```

**改成**：

```
spec  ->  compute()  ->  HANDOFF
             |            ^
             +------------+  测试断言两者相等
```

**只有一个真相来源（spec），文档是被检查的副本。**

**代价**：测试不能告诉你"应该改哪个数"——它只说"文档与 spec 不一致"。
但那是对的：**文档本来就该跟着 spec 走**。

## 决策 4：C 类保留字面

`assert "本节有两个 1.2%" in section` 断言的是**"必须有这个说明"**，
不是"这个数是多少"。

**它不该读脚本**——读了反而会让"说明"变成"数字检查"，
而它要防的是"读者会混淆两个 1.2% 这个语义问题"。

## 关于"同一节内不允许出现两个相同百分比"

上一轮建议加这条断言。**本变更不做**，理由：

它的判据是"同一节内 `X%` 字符串不能重复出现"。但 §0.6 里
`1.1%` 与 `0.5%` 各自只出现一次——**那条断言现在恒真**。

**恒真的断言与没有断言一样**，而它会让人以为"这个形态已被防住"。
真正防住它的是**已经写进 HANDOFF 的那段说明**（"本节有两个 1.2%，分母不同"），
以及它配套的 `test_section_0_6_distinguishes_the_two_1_2_percent`。

## Risks / Trade-offs

| 风险 | 缓解 |
|---|---|
| A 类改成读文档后，文档漏写会红 | 那正是目的 |
| B 类仍需手改 | 显式常量让"人工"可见，不会误以为自动 |
| `compute()` 与生产代码耦合 | 它只读 spec 文件，不 import 业务代码 |

## 不做的事

- **不自动化 B 类**：见决策 1
- **不自动化 C 类**：见决策 4
- **不加"同节不允许重复百分比"**：见上
