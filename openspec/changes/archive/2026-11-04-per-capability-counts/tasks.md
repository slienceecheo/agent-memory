## 2. 新增 `test_per_capability_counts_match_compute`

- [x] 2.1 覆盖三张表：MUST/SHALL 行表、Scenario 表、要求数表
- [x] 2.2 每条做两件事：逐行比对、`sum(分项) == 合计`

  | 检查 | 抓什么 | 能被单独违反吗 |
  |---|---|---|
  | 逐行 == `compute()` | 某行数字写错 | ✅ 改一行 |
  | `sum(分项) == 合计` | 少了/多了一行，或合计被手改 | ✅ 删一行 / 改合计 |

  **不加第三条"合计 == `compute()` 总和"**：它在前两条都通过时必然成立
  （逐行全对 → 分项和 == compute 总和；再等于合计 → 合计 == 总和），
  所以**永远不会被单独违反**。那是恒真断言，不是判据。

  一开始写了三条，写完自己推了一遍发现第三条恒真，删掉了。

- [x] 2.3 定位表格用**表头**，不用字符串包含
  - 第一版用 `f"| `{cap}` | {n} |" in section`，实测漏掉两处：
    - §0.6 里有**两张**两列表 -> MUST 表被读成四类表（`conflict-resolution` 显示 35 而不是 9）
    - 加粗写法不统一 -> `| **`retrieval-apparatus`** | **30** |` 匹配不到
  - 改为 `_parse_capability_table(section, header)` 逐行解析单元格
