## MODIFIED Requirements

### Requirement: 权重命名必须与语义一致

当给一组预注册权重命名时，
MUST 让名字反映"这组权重回答什么问题"，MUST NOT 让它描述数值形状。

新增的组 MUST 按语义命名；`uniform` 是已登记的历史遗留接口名，不适用"按语义命名"这一条，
但 MUST 在 spec 里被显式登记为历史遗留。

权重配置名 MUST NOT 与数据集轴值同名：两者是不同层的概念（排序策略 vs 查询分类），
同名会让 `grep` 一处返回两种东西。

#### Scenario: `(0,0,1)` 不得命名为 `uniform`

- **WHEN** 某组权重是 `(0, 0, 1)`
- **THEN** MUST NOT 命名为 `uniform`
- **AND** MUST 命名为 `cosine_only` 或 `single_signal` 这类语义准确的名字

**为什么**：`uniform` 暗示"各项权重相等"，而 `(0,0,1)` 是"只有一项"。

**还有一个冲突**：`disabled_weights()` 的语义是"只开 base = `(1,0,0)`"。
若 `(0,0,1)` 成为 `uniform`，"全关"与"只开 cosine"会混淆。

| 权重 | 建议名 | 理由 |
|---|---|---|
| `(0,0,1)` | **`cosine_only`** / `single_signal` | 只有一项有信号 |

**`(0.2,0.2,0.6)` 那一行已删除**：它的建议名曾是 `mixed`，而
`mixed` 与数据集轴 `Axis.MIXED` 撞名。见下方场景。

#### Scenario: 权重名不得与数据集轴值同名

- **WHEN** 注册一组新的权重配置
- **THEN** 它的名字 MUST NOT 出现在数据集轴值集合里
- **AND** 判定 MUST 是 `set(PREREGISTERED_WEIGHTS) & {a.value for a in Axis}` 为空集

**实测冲突**（本次删除 `mixed` 的原因）：

| 层 | 定义 | `mixed` 的含义 |
|---|---|---|
| 数据集轴 | `evals/datasets/retrieval_v2.py` 的 `Axis.MIXED` | 混合两轴查询（A + C） |
| 权重配置 | `RerankWeights` 的 `PREREGISTERED_WEIGHTS` 键 | （曾是）0.2/0.2/0.6 |

两者同名、无关。删掉权重侧之后交集为空；删之前是 `{"mixed"}`——
**一条现在红、删完绿的断言**，这正是它可证伪的证据。

**为什么这条断言必须写在测试里，不能写进 `rerank.py`**：
`Axis` 定义在 `evals.datasets.retrieval_v2`（评测层），而 `rerank.py` 是产品层。
产品代码 MUST NOT 依赖评测层。依赖方向决定了断言的位置。

#### Scenario: `uniform` 从未在 v3 里均匀过，这个事实必须写进 spec

- **WHEN** 检查预注册权重表里名为 `uniform` 的那一组
- **THEN** MUST 在 spec 里登记它是历史遗留，MUST NOT 只在代码注释或 docstring 里解释

**三次改名、三次都不均匀**：

| 装置 | `uniform` 的实际取值 | 均匀吗 |
|---|---|---|
| 四特征时代 | 0.25 × 4 | ✅ 唯一一次 |
| v3 三特征时代 | 0.4 / 0.3 / 0.3 | ❌ |
| **加 cosine 后** | **0.2 / 0.2 / 0.6** | ❌ |

**为什么不改名**：`weights_name="uniform"` 在测试里有 48 处调用，
其中 47 处只依赖"这个名字存在且是一组合法权重"——
`test_determinism` 只要求同一配置两次一致，`test_fusion_cap` 只数 `path_returns`，
`test_pool_vectors` 只看向量写入。改名等于改 47 处，而它们的判据与名字无关。

**为什么必须写进 spec 而不是只写注释**：`rerank.py` 的注释已经解释过三次
（"从四特征各 0.25 重算为三特征 0.4/0.3/0.3"），读者仍然误会过。
注释不是权威，spec 是。

## ADDED Requirements

### Requirement: 预注册权重不得互为对象别名

两组预注册权重的数值 MAY 相同，但 MUST NOT 是同一个对象实例。

#### Scenario: 同值但不同对象是允许的

- **WHEN** 两组权重的三元组相同
- **THEN** 它们 MAY 相等（`==` 为 True）
- **AND** MUST NOT 是同一对象（`is` 为 False）

**判据是 `is`，不是 `==`**。这个区别来自一个真实的反例：

| 比较 | `==` | `is` | 判定 |
|---|---|---|---|
| `uniform` vs `mixed`（已删除） | True | **True** | ❌ 别名 |
| `DEFECT18_WEIGHTS` vs `uniform` | True | **False** | ✅ 两个独立字面量 |

`DEFECT18_WEIGHTS` 与默认权重**值相同但对象不同**，它是正确的实现：
改默认权重时它不跟着变（实测：默认改成 0.4/0.3/0.3 后，它仍是 0.2/0.2/0.6）。

#### Scenario: 注释解释数值来源时，MUST 给出可复算的判据而不是"很明显"

- **WHEN** 代码注释解释"某个默认值为什么取这个数"
- **THEN** MUST 写出可复算的判据（不等式、阈值、或指向具体断言）
- **AND** MUST NOT 用"它等于另一个常量"作为唯一理由

**实测反例（`mixed`，已删除）**：默认值的注释原本写着
"**0.2/0.2/0.6 不是'随手调的数字'**：它等于 `mixed`"。
删掉 `mixed` 后，这个理由指向一个不存在的键——
**说明它本来就不是独立成立的解释，只是借了另一个常量的存在。**

**替换后的写法**（判据来自 `test_defect18_authority`）：

```
罚分推翻 base 优势 ⇔ authority / base > d_base = 1 − 0.910 = 0.09
```

比值 `0.2/0.2 = 1.0`，余量 11.1 倍。
**且必须同时写明"这不是唯一正确的值"**：比值 0.75 也成立（余量 8.3 倍，
旧配置 `0.4/0.3` 就是）——**余量只取决于比值，与绝对值无关**。
所以改权重时该守的是比值下限 `0.09`，不是某个具体数。

#### Scenario: 别名让"独立生命周期"的注释无法成立

- **WHEN** 某个常量被文档描述为"与默认同值但独立"
- **THEN** 它 MUST 是独立字面量，MUST NOT 指向默认常量的同一个对象

**实测反例（`mixed`，已删除）**：它的注释写着
"哪天默认改了，它仍应指向 0.2/0.2/0.6"，
而它与 `_DEFAULT_WEIGHTS` 是同一对象。把默认值改成 `0.4/0.3/0.3` 并重新导入后：

| 常量 | 值 |
|---|---|
| `uniform` | 0.4 / 0.3 / 0.3 |
| `mixed` | **0.4 / 0.3 / 0.3**（承诺破裂） |
| `DEFECT18_WEIGHTS` | **0.2 / 0.2 / 0.6**（承诺成立） |

**验证方法必须是"改源码 + 重新导入"，不能是运行时重赋值**：
字典持有对象引用，`module._DEFAULT_WEIGHTS = RerankWeights(...)`
只改模块变量，字典里两个条目都不变——那种测法会得出"都没变"，
看不出别名问题（这是"证伪方法与被证伪的机制不匹配"）。
