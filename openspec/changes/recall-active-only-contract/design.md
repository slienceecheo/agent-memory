## 决策 1：本变更只立契约，不删 `status`

**删 `status` 是中等变更**：

| 项 | 数量 |
|---|---|
| 假 features 构造 | **16 处 / 8 文件** |
| 字段断言 | **5 处** |
| spec requirement | **2 条** |

**而它的合法性来源是"召回只返回 ACTIVE"这个契约。**
那个契约此前没有任何断言。

**所以顺序必须是**：
1. 本变更：立契约（新增 5 条断言）
2. 下个变更：删 `status`（它现在有据可依）

**反过来做会留下一个无法回答的问题**：
"为什么删了一个特征，却没有任何方差证明？"

## 决策 2：必须构造非 ACTIVE，不能只查数据集

**现有三条覆盖都是间接的**：

| 位置 | 测什么 | 漏什么 |
|---|---|---|
| `test_rerank_variance.py:110` | `status_score` 函数的取值数 | 函数有多取值，不代表路径会过滤 |
| `test_v3_capability_boundary.py:140` | 记忆库的 status 集合 | 数据里没有非 ACTIVE，路径去过滤也不红 |
| `test_rerank.py:53` | ACTIVE > CONFLICTED | 值域关系，与池无关 |

**所以本变构造一个含 `SUPERSEDED` 与 `CONFLICTED` 的 store。**

**并且给它们也写向量**：否则 `vector` 测试会假绿
（"没召回"可能只是因为没向量）。

## 决策 3：行为断言与源码断言必须分工

**实测发现**：

| 删掉什么 | 行为断言 | 源码断言 |
|---|---|---|
| `vector.py` 的 SQL 过滤 | **红** | **红** |
| `adjacency.py` 的 Python 过滤 | **绿** | **红** |

**第二行的"绿"是关键**：行为断言守不住 Python 层的二次过滤，
因为 SQL 已经过滤了。

**这个区分必须写进 docstring**，否则读者会以为
"一条行为断言守住了三层过滤"。

**为什么保留这条覆盖不全的行为断言**：
它抓的是 SQL 层——那是最容易被改动的一层（改 SQL 字符串）。
Python 层由源码断言守，两者互补。

## 决策 4：为什么 `condition` 保留而 `status` 删除

**用户上一轮建议 `status` 走 `condition` 的路（独立审计字段），后来自己更正了。**

**决定性的区别是"有没有方差"**：

| 字段 | 池内取值 | 方差 | 审计价值 |
|---|---|---|---|
| `condition` | 0.0 / 0.5 / 1.0 | **有** | ✅ 能看出"查询侧能否拿到条件" |
| `status` | 恒 1.0 | **无** | ❌ 没有任何信息 |

**`condition` 的审计价值是具体的**：它能回答"条件匹配的分布如何"。
而 `status` 恒 1.0，审计它就是审计一个常数。

**正确的类比对象不是 `condition`，是 `temporal_validity`。**
它和 `status` 的删除理由一字不差，都是"所有召回路径只返回 ACTIVE"。

## 决策 5：为什么这 5 条不是"附属项"

**它们不是一个"顺带加的测试"，而是删除的合法性来源。**

**若没有它们**：
- 下一个人问"为什么删 status" -> 答案是"因为它恒 1.0"
- 再问"你怎么知道它恒 1.0" -> 答案是"因为召回只返回 ACTIVE"
- 再问"有断言守着吗" -> **沉默**

**而契约一旦破裂**（某人给某条路径加了非 ACTIVE 支持），
`status` 会重新有方差，那时它应该回来。
**没有契约断言的后果是：它永远不会回来，也没人知道该让它回来。**

## Risks / Trade-offs

| 风险 | 缓解 |
|---|---|
| 构造的 store 与真实池不同 | 行为断言测"路径逻辑"，与池大小无关 |
| 源码断言可能因重构而误红 | 它只查关键字符串（SQL 的 WHERE、Python 的 `is Status.ACTIVE`） |
| `lexical` 的过滤在 `search_text` 里，本变未直接测 | 行为断言已覆盖：lexical 不返回非 ACTIVE |

## 不做的事

- **不删 `status`**（下个变更）
- **不加 `cosine`**
- **不改 `RerankWeights`**
- **不改产物格式**
