## 决策 1：把"数据设计约束"改成"能力边界"

**原本要写的**：v3 数据的设计约束（让 authority 有区分度）。

**为什么不写**：那等于把 v2 已登记的 `condition` 直通缺陷在新特征上重造一遍。

| 装置 | 先验 | 后果 |
|---|---|---|
| v2 | `condition` 匹配 | `SEH@1 = 1.0000`，条件匹配几乎自动第 1 |
| v3（若按原约束造） | `authority` 更高 | 同样退化成单特征决定 |

**而且 authority 更难发现**：`condition` 是显式的查询条件，
`authority` 看起来像"合理的排序信号"。

所以改写为**能力边界 + 防泄漏**：说明 v3 能测什么、不能测什么、
数据侧不得做什么。

## 决策 2：`authority` 是过滤器，不是信号

这是我上一轮判断错的地方。我原本写"authority 是唯一增益来源"。

**实测反例**：

```
gold 唯一最高 authority : 0/10, 0/12
gold mean - distractor  : -0.0244, +0.0213
同层逆序的 case 数      : 0/10, 0/12
```

**第三条是决定性的**：在 auth-only 下，同一 authority 层内部的相对顺序
与融合顺序**完全一致**。所以 authority 的产出可以精确分解为：

```
auth-only 的顺序 = 按 authority 分层，层内按融合顺序
```

它没有提供任何**层内**的区分信息。

**`auth-only = 0.40` 的正确解释**：
不是"authority 选中了 gold"，而是"低 authority 的干扰项被推到后面，
gold 在剩余项里靠融合顺序恰好靠前"。

**sample 上 gold 的平均 authority 比干扰项低**，
进一步证明它不是靠权威赢的。

## 决策 3：`base` 不是负贡献

我上一轮写"`base` 是负贡献（0.20 < 基线 0.30）"。

**这个表述会让人以为"去掉 base 更好"**，而那是错的：
剥掉 base 就等于剥掉裁决规则本身——剩下的只有 authority 分层 + 融合顺序，
而融合顺序正是 base 排序。

**正确表述**：`base` 是 `rrf_norm(fusion_score)`，是融合分的**严格单调变换**。
所以 `base-only` 的 ratio = **融合顺序的 top-1 率**。

```
sample  2/10 = 0.2000     billing 2/12 = 0.1667
```

**这个数测的是召回质量**（三路召回的产物），不是重排能力。

## 决策 4：不加特征、不改权重

**备选：把 vector 余弦分作为第四特征。**

它确实是唯一含语义信号的量（vector 路有语义，但只参与融合，不参与重排）。

**但这是装置变更，不是本变更范围**。而且它需要先回答：
- vector 余弦在池内有没有方差？
- 它与 gold 的相关性是不是又一个"元数据先验"式的泄漏？

**备选：把 authority 权重从 0.3 提到 0.6。**

实测能让 sample 从 0.3000 到 0.4000。但：
- `PREREGISTERED_WEIGHTS` 是**预注册**的，事后改是 HARKing
- 它治不了根：根是"三个特征里没有语义相关性"

**所以两者都不做**，只登记能力边界。

## 决策 5：防泄漏的阈值取 0.05

| 量 | v2 实测 | 阈值 |
|---|---|---|
| `|mean_gold − mean_distractor|` | 0.0244 / 0.0213 | < 0.05 |

**为什么是 0.05**：它比 v2 实测值宽一倍，所以不会因随机波动误报；
同时远小于"authority 差一档"的量级（`user_direct 1.0` vs `user_document 0.66`，
差 0.34）。若数据开始向 gold 倾斜，差值会迅速越过 0.05。

**这不是"提高增益"的阈值，是"检测泄漏"的阈值**——两个方向的用途相反。

## 决策 6：`gold 唯一最高 authority == 0` 是硬判据，不是比例

若允许"少量"（比如 10%），就需要一个"多少算少"的判断，
而那个判断会被"为了达标"往下调。

**0 是唯一不需要解释的阈值。**

## Risks / Trade-offs

| 风险 | 缓解 |
|---|---|
| 断言依赖 v2 数据的具体数字 | 断言的是"同层逆序 == 0"这个机制，数字在 detail 里 |
| 阈值 0.05 可能过严/过松 | 它比实测宽一倍，且远小于单档差距 0.34 |
| 有人日后加第四特征 | 本变更不阻止，但要求先登记它与 gold 的相关性 |

## 不做的事

- **不造 v3 数据**
- **不改权重、不加特征**
- **不改任何门禁判据**
