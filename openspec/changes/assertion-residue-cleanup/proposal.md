## Why

**上一轮的三处修正都成立了，但留下了三个"小残留"。**
而本轮的教训正是**这些小残留会累积**。

### 残留 1：`[0.4, 0.7]` 宽区间对漂移无感知

比例的真实变化轨迹：

| 归档 | 分母 | 比例 |
|---|---|---|
| 第二十六次 | 365（漏 `retrieval-apparatus`） | 50.7% |
| 第二十七次 | 365（仍漏） | 49.9% |
| 第二十八次 | **380**（补齐） | **48.05%** |

**前两行的分母是错的**（漏了一个能力），而宽区间 `[0.4, 0.7]` 对错值也判绿。

**这个区间的判据是错的**：它防的是"剧变"（统一规范词 / 删光规范词），
而实际发生的漂移是 1–2 个百分点——**宽区间完全感知不到**。

### 残留 2："绿/红"不对称检查依赖表格措辞

```python
assert "绿" in adjacency_row[0] and "红" in adjacency_row[0]
```

**这条判据的真正内容是"两个单元格不相等"**，但它依赖表格用了「绿/红」这两个字。

**若表格改成「通过/失败」，断言会失效**——而它想表达的"行为与源码结果不同"仍然成立。

### 残留 3：`359` 还在 docstring 里

`test_spec_normative_words.py` 里两处提到 `359`，但没有时间标记。

**下一个读者会以为它是当前值。**

## What Changes

**1. 新增"分母必须等于 `CAPABILITIES` 的 Scenario 之和"的断言**

```python
def test_denominator_equals_capability_scenario_sum():
    """分母不能漏能力——宽区间抓不到这个。"""
```

**这条判据是精确的**，不需要区间。

**宽区间保留**：它抓"剧变"（统一规范词），与分母断言分工不同。

**2. 不对称检查改成"两个单元格不相等"**

```python
cells = [c.strip() for c in adjacency_row[0].strip("|").split("|")]
assert cells[1] != cells[2]
```

**不依赖「绿/红」这两个字**，只依赖"两者不同"这个事实。

**3. `359` 加时间标记**

```
> 359 是第 26 次归档时的值（当时 evaluation-harness 172，现在 183）。
> 本数字只作历史记录，判据不依赖它。
```

## 验收

| # | 判据 | 可被违反的形式 |
|---|---|---|
| 1 | 分母漏一个能力 | **分母断言必须红**（宽区间不会） |
| 2 | 两个单元格都改成「红」 | 不对称断言必须红 |
| 3 | 表格改成「通过/失败」但两者不同 | 不对称断言**仍绿**（不依赖措辞） |
| 4 | docstring 里 `359` 无时间标记 | 必须红 |
