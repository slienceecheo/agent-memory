# Spec Delta

## Purpose

定义与外部模型服务交互的行为契约：如何解析被强制分块的响应、如何处理推理内容与正文的
区分、如何缓存 embedding、以及如何在这个基础上保证同一请求的重复执行可得到相同结果。
它不规定用哪个库实现，只规定对外可观察的行为。

## ADDED Requirements

### Requirement: 分块响应收拢

系统 SHALL 能处理服务端返回的分块（SSE）响应，并在调用方未要求流式输出时，
将其收拢为一条完整的消息后返回。

#### Scenario: 服务端强制分块
- **WHEN** 请求中声明不需要流式输出，但服务端仍返回 `data:` 分块序列
- **THEN** 系统返回一条完整消息，包含拼接后的正文与最终 usage，且不向调用方暴露分块细节

#### Scenario: 分块以结束标记收尾
- **WHEN** 分块流以结束标记终止
- **THEN** 系统正常结束解析，不把结束标记当作正文内容

#### Scenario: 流意外中断
- **WHEN** 分块流在结束标记出现前断开
- **THEN** 系统抛出明确的错误，指出响应不完整，而不是返回一段被截断的正文

#### Scenario: 单块中包含完整结果
- **WHEN** 服务端只返回一个包含完整内容的分块
- **THEN** 系统仍能正确解析，行为与多块情形一致

### Requirement: 推理内容与正文分离

系统 SHALL 区分响应中的推理内容与最终正文，并在默认配置下丢弃推理内容，
同时统计其占用的 token 数。

#### Scenario: 响应同时包含推理与正文
- **WHEN** 返回内容中推理部分在前、正文在后
- **THEN** 调用方只拿到正文，且结果中带有推理 token 数与推理浪费比例

#### Scenario: 只有推理没有正文
- **WHEN** 响应在推理结束后被截断，没有输出正文
- **THEN** 系统明确报错，指出正文为空，并把推理内容保留在错误详情中供排查

#### Scenario: 没有推理内容
- **WHEN** 响应不含推理内容
- **THEN** 推理 token 数为 0，浪费比例为 0，正文正常返回

### Requirement: Embedding 双模式编码

系统 SHALL 区分文档侧与查询侧两种编码模式，并在调用外部服务时传递对应的模式标记。
两种模式 MUST 使用相同的模型与向量维度。

#### Scenario: 文档侧编码
- **WHEN** 为待入库的文本生成向量
- **THEN** 请求使用文档模式标记

#### Scenario: 查询侧编码
- **WHEN** 为检索查询生成向量
- **THEN** 请求使用查询模式标记

#### Scenario: 维度一致性
- **WHEN** 同一批文本以相同维度编码
- **THEN** 所有向量长度相同；若服务端返回的维度与请求不符，系统报错

#### Scenario: 混用模式被拒绝
- **WHEN** 调用方试图用文档向量与查询向量之外的未定义模式
- **THEN** 系统在发起请求前就拒绝，而不是把非法值透传给服务端

### Requirement: Embedding 缓存

系统 SHALL 把所有 embedding 结果缓存到磁盘，缓存键 MUST 同时包含模型名、维度、
编码模式与原文。缓存命中时 MUST NOT 发起网络请求。

#### Scenario: 相同请求命中缓存
- **WHEN** 以完全相同的模型、维度、模式与文本再次请求
- **THEN** 直接返回缓存结果，网络调用数为 0

#### Scenario: 任一字段变化则未命中
- **WHEN** 文本相同但编码模式不同
- **THEN** 视为不同缓存条目，各存一份，不互相覆盖

#### Scenario: 缓存损坏
- **WHEN** 缓存文件内容无法解析
- **THEN** 系统把该条目视为未命中并重新请求，同时在日志中记录一条警告

#### Scenario: 批量请求部分命中
- **WHEN** 一次请求 10 条文本，其中 6 条已有缓存
- **THEN** 只为其余 4 条发起网络请求，返回结果顺序与输入顺序一致

### Requirement: 批量请求分片

系统 SHALL 将超过服务端上限的批量请求自动分片，并保持返回结果与输入顺序一一对应。
任一分片失败时 MUST 整体失败，不返回部分结果。

#### Scenario: 请求数超过单批上限
- **WHEN** 一次传入的文本数超过单批上限
- **THEN** 系统自动拆成多批依次发送，合并后顺序与输入一致

#### Scenario: 某一分片失败
- **WHEN** 三个分片中第二个返回错误
- **THEN** 整次调用失败并指出失败的是哪一批，而不是返回前一批的结果

### Requirement: 网络错误分类与重试

系统 SHALL 区分可重试错误（超时、限流、服务端 5xx）与不可重试错误
（鉴权失败、请求参数非法、模型不存在），并只对前者重试。

#### Scenario: 限流后成功
- **WHEN** 首次请求返回限流错误，重试时成功
- **THEN** 调用最终成功，且结果中记录重试次数

#### Scenario: 鉴权失败
- **WHEN** 请求返回鉴权失败
- **THEN** 立即失败，不重试，并给出可操作的提示

#### Scenario: 重试耗尽
- **WHEN** 连续重试达到上限仍失败
- **THEN** 系统抛出明确错误，包含最后一次的原始错误信息与总尝试次数
