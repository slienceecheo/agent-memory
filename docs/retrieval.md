# 检索层：三路召回与 fitness-for-use 重排

## 三路召回

| 路径 | 实现 | 服务什么 |
|---|---|---|
| 词面 | `items_fts`（中文 bigram）+ `bm25()` 排序，索引**原文** | 用用户实际说过的话找到记忆 |
| 向量 | numpy 暴力余弦 | 字面不同但语义相近 |
| 条件兄弟 | 同逻辑键、不同 `condition` | BRANCH 场景的 gold 唯一可能的召回路径 |

**邻接刻意不做跨关系**：那条路的 gold 就是查询命中自身（被"排除自身"规则去掉），
永远召不回目标，只会贡献干扰项。

## RRF 而不是加权分数

`score = Σ 1/(k + rank_i)`，k=60。

BM25 无界、余弦有界，加权前必须归一化，而归一化参数随数据集漂移。
RRF 只用排名，跨数据集稳定。

**代价**：丢掉"差多少"。对三路召回这个量级，稳定性更重要。

**边界**：多路命中不一定总赢——当一路列表很长时，它在尾部的贡献很小，
可能输给另一路头部。条件是列表长度 < k+2。

## 四特征重排

```
final = w_base·base + w_cond·condition + w_auth·authority + w_status·status
```

| 特征 | 计算 | 值域 |
|---|---|---|
| `base` | RRF 分数 / 最大分数 | [0,1] |
| `condition` | 槽位集合 Jaccard；一方缺失取 0.5 | [0,1] |
| `authority` | third_party 0.0 → user_direct 1.0 | [0,1] |
| `status` | ACTIVE 1.0 > CONFLICTED 0.5 > SUPERSEDED 0.2 > RETRACTED 0.0 | [0,1] |

**每个特征必须落在 [0,1]，越界即报错。** 未限定值域时，`recorded_at` 这类
大数会压过任何 [0,1] 的权重，权重搜索失去意义。

**全部特征关闭时**退化为 `base` 排序，且不触发权重校验（走独立分支）。

### 被删掉的两个特征

原设计有五个特征。审查实测其中两个在 ACTIVE-only 候选集上**恒为常数**：

- `temporal_validity`：所有召回路径只返回 ACTIVE，恒为 1.0
- `recency`：场景文件没有时间字段，全部同一 `BASE_TIME`

留着它们会让"重排有效"看起来成立，实际排序没变。
`test_rerank_variance.py` 对真实数据断言每个特征确实有方差——
任一项退化会直接指出是哪个。

## 条件槽位：中英双向

实测 dev/test 用英文（`coding`、`prod`、`night`），independent 用中文
（`法定节假日`、`客户应酬`）。单向词表会让跨语言永远不匹配。

当前覆盖率：30/30 条件 100% 结构化。

**但这个数字要配合另一个数字读**：90 条场景里只有 30 条**有**条件。
其余 60 条上 `condition_match` 恒为中性 0.5，没有区分度。

## 语义等价：只服务读路径

三分类：`等义 / 互补 / 无关`。

**它不参与 C3 的 `decide()`**。让它回流写路径会让"规则顺序"的测试失去意义，
也会把读路径的收益冒充成判定能力的提升。

唯一消费者是**去重阶段**：对 top-K 内的候选两两比对，判为等义则只保留
融合分更高者。产出必须可观测——`DedupStats.before` 与 `.after` 的差
就是去重的实际效果。

**实测**：互补类 6/6，等义类 **2/4**（未达 3/4 阈值）。
错误方向一致：把等义判成互补。这个方向更安全（不合并 v.s. 错删），
但代价是去重对等义类基本失效。

## 指标

| 指标 | 定义 | 为什么需要 |
|---|---|---|
| `SEH@K` | gold 是否进前 K | 集合命中 |
| `SRS` | `1/rank`，未召回为 0 | **唯一定义**，区分"进前 5 但排第 5"与"排第 1" |

`1/rank`、`1-(rank-1)/N`、`1-rank/N` 三者中间排名顺序一致但数值不同，
跨查询不可比。本实现固定用 `1/rank`。

## 失败归因：三类而非四类

| 类 | 判定 |
|---|---|
| `NOT_IN_POOL` | gold 不在候选池（池构建问题） |
| `LOW_RANK` | gold 在池中，但融合后排名就 > K |
| `RERANK_DROPPED` | 融合后在 K 内，被重排挤出 K |

**必须保留未截断的融合排名**，否则第 2 类与第 3 类无法区分。

**只统计检索失败**，不复用 C3 的判定错误——那是写路径的问题。

## 一个必须记录的限制

三种池难度里，只有最低的那种可评估：

| 模式 | 可评估 | 结果 |
|---|---|---|
| `unrelated` | 26/30 | SEH=1.000 |
| `same_relation` | 0/30 | 全部跳过 |
| `adversarial` | 0/30 | 全部跳过 |

原因：independent 集 29 个 relation 里 28 个只出现一次，
同主题干扰项选不出来。

**所以当前指标只回答"能不能在无关记忆里找到相关的"，
不回答"能不能在相似记忆里挑对"。** 后者才是真实难度。
详见 `docs/reports/c4-pool-limitation.md`。

## 规模边界

向量召回用暴力余弦。候选 10^4 量级时全库点积 < 5ms，
ANN 在这个量级上收益为零、依赖成本为正（Windows 的 wheel 兼容）。

**超过 10^6 条时应重构此层。** 这个数字写在这里，而不是"将来再优化"。
